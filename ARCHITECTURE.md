# friendbuy-ai — Architecture Plan & Production Checkpoints

> Generated by multi-agent workflow analysis of the current codebase.
> Every file, gap, and checkpoint was verified by independent agents.

---

## Why vector-only is not enough

The current system treats every file as an **isolated text blob**.  
A question like *"what services does campaign creation touch?"* requires knowing:

```
CampaignController.create_campaign()  (api repo)
  └─CALLS→  CampaignService.create()
              ├─CALLS→  RewardService.issue()         (payments repo)
              ├─CALLS→  CampaignRepository.save()     (api repo)
              └─EMITS→  POST /events  (AnalyticsService, analytics repo)
```

That **causal chain lives in the graph**, not in any individual chunk's embedding.
Vector search returns the 5 most semantically similar chunks — none of which
reveals the traversal path through the system.

### Today's relationship blindspots (confirmed gaps)

- `"What services does campaign creation touch?"` — no call graph to traverse
- `"What calls the referral API?"` — no reverse-dependency lookup
- `"What repos share this utility function?"` — each repo is siloed, no cross-repo identity
- `"What are all API endpoints exposed by this service?"` — no AST route extraction
- `"What changed in the last two weeks?"` — git history not indexed
- `"What does file X in fbt-retailer-app import from fbt-influencer-app?"` — no import graph
- `"Full request lifecycle from widget to backend?"` — no HTTP contract edges
- `"What implements interface Y?"` — no implements/extends graph

### Today's production blockers (confirmed)

- Synchronous indexing blocks the FastAPI event loop (POST /index will timeout)
- `SystemExit` used as cross-module error signal — wrong in a server context
- `shutil.rmtree` before new embeddings are computed — crash = destroyed index, no rollback
- No doc deduplication — N index runs = N copies of every chunk, precision degrades silently
- `load_vector_store()` re-opens Chroma + Ollama health check on **every query**
- No rate limiting on `/ask` — concurrent requests exhaust Ollama + Anthropic connections
- Relative `chroma_persist_dir` — different CWD = silent empty knowledge base
- No `GET /ready` probe — load balancer has no way to know the service is ready
- Zero test suite — no regression safety net
- No embedding model version tracking — silent incompatibility after model updates

## Graph Database Choice: **Kuzu** (kuzu-python)

| Property | Detail |
|----------|--------|
| **pip install** | `pip install kuzu` |
| **Type** | Embedded, in-process, no separate server |
| **Query language** | openCypher (compatible with Neo4j Cypher) |
| **M1 memory** | ~100-300 MB — leaves headroom for Ollama |
| **Why not Neo4j** | Requires JVM, 2-4 GB RAM for server alone |
| **Why not NetworkX** | No Cypher, no persistent query engine |
| **Why not FalkorDB** | Requires separate Redis-like server process |
| **Fallback** | `pip install falkordb-lite` if Kuzu has issues |

> Note: The research agent identified "LadybugDB" as an active Kuzu fork —
> but the canonical embedded Cypher DB for Python on M1 is simply `kuzu`.
> Use `pip install kuzu` directly.

## Graph Schema

### Nodes

| Label | Key Properties |
|-------|---------------|
| `Repo` | repo_id (SHA256 of name), name, local_path, last_indexed_sha |
| `File` | file_id (SHA256 of repo+path), repo_name, file_path, content_hash, chunk_ids |
| `Class` | class_id (qualified_name+file_id), name, qualified_name, start_line, end_line, docstring |
| `Function` | function_id, name, qualified_name, is_async, is_method, decorator_names, docstring |
| `APIEndpoint` | endpoint_id (method+path+file_id), http_method, path_pattern, full_path, framework |
| `Feature` | feature_id, name, description, entry_endpoint_ids, root_function_ids, repo_names |
| `Module` | module_id, name, module_path, repo_name, is_external |

### Edges

```cypher
(File)-[:IMPORT]->(File)                   // A imports from B
(File)-[:IMPORT_EXTERNAL]->(Module)        // A imports third-party package
(Function)-[:CALLS_FUNCTION]->(Function)   // A calls B (with confidence score)
(Function)-[:BELONGS_TO]->(Class)          // method → class
(Class)-[:BELONGS_TO_FILE]->(File)
(Function)-[:BELONGS_TO_FILE]->(File)
(File)-[:EXPOSES_ENDPOINT]->(APIEndpoint)  // file defines route
(APIEndpoint)-[:HANDLES]->(Function)       // route → handler function
(Class)-[:INHERITS]->(Class)               // extends
(Class)-[:IMPLEMENTS]->(Class)             // implements interface (TS)
(Function)-[:CROSS_REPO_CALL]->(APIEndpoint) // HTTP/Kafka/DB cross-repo edge
(File)-[:BELONGS_TO_REPO]->(Repo)
(File)-[:CONTAINS_CLASS]->(Class)
(File)-[:CONTAINS_FUNCTION]->(Function)
```

### Example: "What does campaign creation touch?"

```cypher
MATCH path=(entry:APIEndpoint {path_pattern: '/campaigns'})-
  [:HANDLES]->(h:Function)-
  [:CALLS_FUNCTION|CROSS_REPO_CALL*1..4]->(target)
RETURN path, nodes(path), relationships(path)
```
Returns: CampaignController → CampaignService → RewardService → PaymentsAPI (cross-repo)

## Hybrid Retrieval Flow (12 steps)

```
1.  Semantic cache check         (5ms)   — cosine ≥ 0.93 → return cached answer
2.  Entity extraction            (10ms)  — trie lookup on graph node names from query
3a. Dense vector search          (100ms) — ChromaDB cosine, top-20, score ≥ min_threshold
3b. Sparse BM25 search           (100ms) — rank-bm25, top-20  [concurrent with 3a]
4.  Graph traversal              (50ms)  — Kuzu Cypher MATCH path (1-3 hops) [concurrent]
5.  Graph-guided chunk fetch     (30ms)  — fetch ChromaDB chunks for graph-discovered nodes
6.  Graph-aware pre-filter       (5ms)   — keep chunks with graph entity overlap (GAHR-MSR)
7.  RRF fusion                   (5ms)   — Reciprocal Rank Fusion of 4 ranked lists
8.  Cross-encoder reranking      (200ms) — flashrank top-50 → top-10 (optional flag)
9.  Graph relationship summary   (20ms)  — structured summary string from traversal result
10. Qwen context curation        (500ms) — local model removes noise, stitches context
11. Claude answer + prompt cache (1000ms)— cache_control on system + graph blocks
12. Cache population (async)     (10ms)  — store answer for future cache hits
```

### CP4 — Cross-Repo Inference + Semantic Cache `[HIGH complexity]`
**Goal:** Auto-detect cross-repository edges (HTTP calls, Kafka topics, shared DB schemas).

**Deliverables:**
- `indexer/cross_repo_linker.py` — tree-sitter queries for `axios/fetch/httpx/requests` HTTP calls with URL extraction; docker-compose/`.env` base URL → service name resolution; OpenAPI spec parsing for caller-provider matching; Kafka producer/consumer topic matching; emits `CrossRepoCall` edges with confidence scores

- `retriever/reranker.py` — `flashrank` cross-encoder; lazy model load; `rerank(query, candidates, top_n)` 
- `config.py` — add `semantic_cache_threshold`, `use_reranker`, `cross_repo_confidence_threshold`
- `api/server.py` — `GET /graph/traverse?entity=X&hops=2`; `POST /cache/invalidate`
- `requirements.txt` — add `flashrank>=0.2`

**New files:** `indexer/cross_repo_linker.py`, `retriever/semantic_cache.py`, `retriever/reranker.py`

## Migration Path (backward-compatible at every step)

1. **CP0 first** — fixes all production blockers, no new dependencies
2. **CP1** — `pip install kuzu tree-sitter*` then `python cli.py index --reindex`; AST chunks replace character chunks; graph bootstrapped with File+Repo nodes
3. **CP2** — `python cli.py index --reindex`; full graph populated; `python cli.py graph-stats` to verify
4. **CP3** — hybrid retrieval wired in; `--no-graph` flag preserves vector-only for A/B comparison
5. **CP4** — `python cli.py index` triggers cross-repo linker; second identical query hits cache
6. **CP5** — run `python eval/ragas_eval.py` to establish quality baseline before enabling in production; add to CI
7. **Rollback at any point**: delete `./friendbuy-graph-db/` and use `--no-graph` → instant vector-only fallback
